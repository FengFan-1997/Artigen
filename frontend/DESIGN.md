# Design System: Artigen Design Agent

## Overview

**Creative North Star: “正在组装的明亮工作简报”**

Artigen Design Agent 是一个操作型工作区，不是通用聊天气泡界面。首屏把自然语言需求当作整份简报的起点：标题、说明、输入框和任务建议沿中央轴排列；第一条消息发出后，同一输入框停靠到底部，请求在上方展开为对话、执行计划、授权和交付物。用户始终留在同一空间里理解发生了什么、由谁执行、花费多少以及下一步能做什么。

视觉表达明亮、克制、带有轻微的工具感。大面积白色与暖灰色提供安静的工作纸面，近黑色承担结构，酸性绿只标记品牌和执行中的关键节点。页面通过细描边、色块分区和少量阴影建立层级，不使用紫色品牌表达，也不把执行卡伪装成普通消息。

**Key Characteristics:**

- 白色主画布配暖灰历史栏，形成“工作纸张 + 工具边栏”的双层空间。
- 超大紧凑标题建立入口识别度，正文与元数据保持低调、直接。
- 酸性绿只出现在品牌信号、执行器图标、进度和主要执行动作上。
- 对话、执行、费用、授权和交付物在一条纵向工作流中连续呈现。
- 桌面保留持久历史轨；移动端把历史变成带遮罩、焦点管理和返回焦点的抽屉。

**The Brief, Not Messenger Rule.** 新增界面必须像一份正在形成的项目简报：标题、计划、证据与控制项比装饰性聊天气泡更重要。

## Colors

主色系统由暖白纸面、纯白表面、近黑墨色与酸性绿信号组成。YAML frontmatter 中的七个颜色是该页面已实现并复用的 CSS 自定义属性；其他状态色是组件内的语义值，不应擅自升级为全局 token。

### Primary

- **Acid Signal** (`{colors.acid}`)：品牌标记、助手标记、执行器图标、已完成步骤、主要执行按钮。用于明确“可以行动”或“正在执行”，不作为大面积背景。
- **Execution Green** (`{colors.acid-dark}`)：运行状态点、进度条和建议箭头。它承担比亮酸性绿更稳重的状态信息。

### Neutral

- **Working Paper** (`{colors.paper}`)：页面最外层底色，提供轻微暖度。
- **Clean Surface** (`{colors.surface}`)：会话主画布、输入框和高优先级卡片表面。
- **Structural Ink** (`{colors.ink}`)：标题、正文、图标轮廓和关键边界。
- **Muted Copy** (`{colors.muted}`)：解释文字、时间、隐私说明和低优先级元数据。
- **Hairline** (`{colors.line}`)：顶栏、侧栏、标题区和卡片之间的细分隔线。

### Semantic States

这些颜色是现有组件中的局部语义样式，不属于全局 token：

- 运行与排队使用橄榄绿状态点，并配酸性绿半透明外环。
- 成功使用深绿；警告、预算阻断与授权等待使用琥珀色。
- 失败、拒绝、取消和删除使用低饱和砖红色。
- 等待上传使用浅蓝色提示块；本地处理使用浅绿提示块。
- 授权卡使用暖黄色背景与琥珀描边，使外部写操作与普通执行步骤明确分离。

**The Acid Is Evidence Rule.** 酸性绿必须对应品牌、执行状态或明确动作；不要把它扩展成普通装饰色。

**The Honest State Rule.** 成功、失败、警告、等待文件和等待授权必须继续使用彼此可区分的语义组合，且不能只靠颜色传达状态；现有界面同时提供文字标签、图标或结构位置。

## Typography

页面没有设置独立 `font-family`，所有文本继承 Artigen 应用现有字体。因此此文档不指定或推测字体家族；实现新界面时应继续继承应用字体，而不是引入新的展示字体。

### Hierarchy

- **Display**（780，`clamp(38px, 5vw, 72px)`，0.98，字距 `-0.055em`）：只用于零状态主问题，居中且紧凑。
- **Headline**（`clamp(28px, 4vw, 48px)`，1.05，字距 `-0.045em`）：用于会话标题，宽度限制为 760px。
- **Lead Body**（16px，1.7）：用于零状态说明，最大宽度 690px，居中排版。
- **Conversation Body**（继承字号，1.65）：用于用户与助手消息，保留换行。
- **Card Title**（15px）：用于执行卡主标题。
- **Metadata**（9–12px）：用于状态、报价、步骤、文件、隐私说明和历史时间；重要小标签使用约 780–850 的高字重。
- **Eyebrow**（11px，820，字距 `0.16em`）：用于 `ARTIGEN DESIGN AGENT` 与执行摘要。执行卡内部 kicker 使用 9px、约 `0.1–0.12em` 字距并大写。

标题用紧凑字距和短行形成视觉锚点，正文以较松行高维持阅读。中文与英文共用同一层级，不依赖全大写来表达中文状态；英文标签可以大写并增加字距。

**The Inherited Typeface Rule.** 保持现有应用字体继承关系；除非全局品牌系统先发生变化，否则不要在该工作区局部引入字体。

**The Small Type Has a Job Rule.** 9–12px 文本只用于短标签和辅助元数据；操作后果、授权范围、错误恢复和正文不得被压缩成装饰性小字。

## Layout

### Desktop shell

- 应用标题栏下方的工作区高度为 `calc(100vh - 80px)`。
- 历史栏默认宽 252px，收起后为 64px；主画布始终使用 `minmax(0, 1fr)` 占据剩余空间。
- 会话顶栏高至少 64px，左右内边距 30px；未进入会话时分隔线透明，进入会话后显示细线。
- 零状态在剩余视口中垂直居中，外边距为上 110px、左右 30px、下 60px。
- 首屏输入区、隐私说明和建议区最大宽度 820px；三张建议卡等分一行，间距 8px。
- 会话标题最大宽度 980px；消息、执行卡、授权块和停靠输入框最大宽度 920px。
- 消息滚动区顶部留 104px，左右留白使用 `clamp(22px, 7vw, 110px)`，底部留 220px 给停靠输入框。
- 对话条目按 24px 垂直节奏分隔；执行卡与前后内容保持独立块级边界。

### Conversation geometry

- 用户消息靠右，正文最大宽度为内容区的 72%；助手消息靠左并由 30px 的酸性绿 `A` 标记引导，正文最大宽度为 78%。
- 执行卡不是气泡：它横跨内容主列，内部依次为执行器头部、计划、元数据、风险或交付内容、进度和动作区。
- 执行步骤使用 28px 圆形编号和 1px 纵向连线，单步最小高度 44px。
- 元数据使用可换行的紧凑标签组；标题、状态、报价、自动上限和已用点数保持可扫描。
- 底部输入区固定在会话画布底部，以白色渐隐阴影与滚动内容分离；滚动内容必须保留足够底部空间，避免被输入区遮挡。

### Responsive behavior

- **900px 及以下：** 双栏网格切换为单列；历史栏变成固定抽屉，宽度为 `min(84vw, 320px)`，关闭时移出视口。主顶栏显示“历史”按钮，正常运行状态隐藏，只保留不可用状态；模型标签仅保留自动预算上限。
- **900px 及以下：** 零状态左右内边距缩为 18px，建议卡由三列变单列；消息区改为上 92px、左右 16px、下 260px；用户与助手正文最大宽度都为 88%；停靠输入区左右内边距缩为 12px。
- **640px 及以下：** 执行卡头部与主体内边距缩为 14px；元数据变为两列；授权动作垂直堆叠，按钮最小高度 44px；页脚允许换行，交付物占满可用宽度。
- **620px 及以下：** 输入框圆角由 22px 调整为 18px；隐藏 `LOCAL FIRST`；附件按钮文案缩短为“附件”。

**The One Spatial Frame Rule.** 首条消息后只改变内容状态：输入框从中央移到下方，历史和会话仍处于同一工作区，不能跳转成另一套视觉壳。

## Elevation & Depth

系统以平面分区和细描边为主，只在需要明确层级或移动关系时使用阴影。

- **品牌硬阴影：** 零状态品牌信号使用 8px × 8px 的纯墨色投影，配合轻微 `-2deg` 旋转，是页面最鲜明的图形签名。
- **输入框悬浮层：** 默认使用 `0 16px 50px rgba(16,17,15,.09)`；聚焦后同一阴影略加深，并加入 3px 酸性绿半透明焦点环。
- **执行卡：** 使用 `0 10px 30px rgba(16,17,15,.06)`，只提供轻微抬升，不做浮夸玻璃效果。
- **停靠输入区：** 使用向上的白色柔化阴影，与下方固定层形成淡出边界。
- **移动历史抽屉：** 打开时使用向右扩散的深色阴影，并叠加半透明黑色遮罩。
- **通知：** 深色浮层使用更明显的下方阴影，确保它在工作区上方被识别为临时反馈。

**The Flat-by-Default Rule.** 常驻表面依靠色差和 1px 描边分层；阴影只用于输入焦点、固定层、抽屉、通知或签名图形。

## Shapes

圆角语言柔和但不胶囊化所有内容。大容器使用 18–22px，任务建议与普通信息块使用 10–14px，小型控制使用 8–10px；圆形仅留给状态点、步骤编号、新建按钮和发送按钮。

- 输入框：桌面 22px，窄屏 18px。
- 用户消息：非对称 `22px 22px 4px 22px`，用右下尖角表达发送方向。
- 执行卡：18px；建议卡：14px；授权卡与通知：12px。
- 执行器图标和多数提示块：10px；元数据、附件和动作按钮：8–11px。
- 状态 chip 和澄清选项使用 999px 胶囊形，但只承载短文本。
- 所有功能性描边通常为 1px；酸性绿品牌块可使用硬阴影强化轮廓。

**The Radius Follows Scope Rule.** 容器越大，圆角越大；不要把长段内容或整张执行卡改成胶囊形。

## Components

### Application shell and history

- 桌面历史栏使用暖灰背景、右侧细线和白色活动会话卡。历史项为 12px 内边距、12px 圆角；悬停只改变背景，选中态再加入边框。
- 历史栏可收起为 64px 图标轨；在移动端完全转为抽屉，不保留压缩轨。
- 抽屉打开后背景内容不可交互；点击遮罩或按 Escape 关闭。打开时焦点移到抽屉首个按钮，Tab 在抽屉内循环，关闭后恢复到触发按钮。
- 顶栏运行状态同时包含色点与文字；不可用状态不可被移动端响应式隐藏。

### Opening state

- 品牌信号为 62px 方形酸性绿纸张图形，包含三条黑色横线、18px 圆角、硬阴影和轻微旋转。
- eyebrow、主问题、说明、输入框、隐私说明和建议任务按单轴顺序排列。
- 任务建议点击后只填入输入框，不自动发送；换一组按钮每次轮换三条建议。

### Composer

- 默认输入框为白色表面、1px 灰绿描边、22px 圆角和柔和阴影；紧凑态只降低文本区最小高度。
- 文本区字号为 16px、行高 1.55，不允许手动拖拽；内容变化时自动增高，零状态最小 68px、停靠态最小 54px、最大 180px。
- Enter 发送，Shift+Enter 换行；输入法组合期间 Enter 不触发提交。没有有效文字或正在发送时，发送按钮禁用。
- 聚焦时边框切换为近黑色，并显示酸性绿半透明焦点环。
- 附件 chip 显示文件名、大小和移除按钮；文件名最大宽 180px，超出时省略。输入区最多保留十个选择文件。
- 附件按钮为浅色描边按钮；发送按钮为 42px 圆形酸性绿按钮。可发送时悬停上移 1px 并产生 5px 黑色底边；禁用时切换为灰色而非仅降低透明度。
- “LOCAL FIRST” 是隐私承诺，不是装饰标签；移动端可以缩短或隐藏，但其完整解释必须保留在输入区附近。

### Messages and clarification

- 用户消息使用浅灰绿气泡并右对齐；助手消息不使用有色大气泡，而以酸性绿 `A` 标记和自然文本列展示。
- 消息附件以白色小标签呈现文件名和大小。
- 澄清问题使用描边胶囊；“按推荐直接做”使用近黑底白字，体现明确的继续路径。
- 规划中状态包含三个 7px 深绿圆点，以 900ms 交错动画和说明文字共同表达，不得仅显示无文字 loading。

### Execution card

- 卡片头部使用暖灰表面、18px/16px 内边距和底部分隔线；38px 酸性绿执行器图标必须与真实路由类型匹配。
- 执行器类别以 9px 大写 kicker 展示，任务标题为 15px；状态 chip 位于右侧并使用 `role="status"` 与 `aria-live="polite"`。
- 计划步骤通过编号、连线、文字颜色、酸性绿填充和焦点环区分已完成、进行中和待处理。
- 元数据区必须如实呈现执行器、真实报价、自动上限和已用点数；小屏变成两列，不得删除关键财务信息。
- 本地工具、等待上传、预算阻断、失败和授权分别使用独立提示块。状态文案需说明文件是否上传、任务是否创建、点数是否冻结/扣除/退还，以及用户如何恢复。
- 交付物用带缩略图的白色描边卡展示；Agent 交付物同时显示文件名与验证状态。
- 进度条高 3px，使用深绿填充并以左侧为变换原点；进度变化使用 220ms ease。
- 页脚首先显示财务或步数说明，再显示主要动作、取消和高级详情。移动端允许换行并使动作等宽。

### Authorization

- 外部写操作使用暖黄色授权卡，与普通执行内容明确隔开；kicker 指明“外部写操作”或“需要接管”。
- 授权内容必须包含变更摘要、影响、接收方，以及持续授权时的站点、动作类型、30 分钟闲置失效和可撤销范围。
- 一次性批准为近黑主按钮；会话持续授权为浅色绿描边按钮；拒绝为白底红色描边按钮。移动端三者垂直排列并增大触达高度。
- 被阻断的高风险动作不显示批准按钮，只提供安全接管链接。

### Notices and failure recovery

- 全局 notice 是右下角深色浮层，包含具体反馈和关闭按钮；它使用 `role="status"`。
- 失败块使用 `role="alert"`，明确失败代码、点数处理和恢复方式。
- “载入原要求并修改”会把原始目标放回底部输入框；恢复路径必须保留上下文，不能只给“重试”空操作。

## Do's and Don'ts

### Do:

- **Do** 让用户先描述结果，再展示被选择的执行器与执行细节。
- **Do** 在所有执行卡中如实显示执行器、报价、自动上限、已用点数和最终结算。
- **Do** 让附件默认留在浏览器，仅在确定云端执行路径后上传，并在输入区附近重复说明。
- **Do** 使用 820px、920px 和 980px 三个已实现内容宽度建立从输入、执行到标题的清晰层级。
- **Do** 保留桌面收起轨、移动抽屉、Escape 关闭、焦点陷阱和关闭后焦点恢复。
- **Do** 为运行状态、授权、错误和通知保留文字标签及合适的 live region。
- **Do** 尊重 `prefers-reduced-motion`：将过渡和动画缩至接近零，并只播放一次。
- **Do** 保留中英文切换后的同等信息量，尤其是隐私、预算、授权范围和失败恢复说明。

### Don't:

- **Don't** 把页面改成大面积彩色气泡、紫色品牌或泛化的聊天机器人外观。
- **Don't** 在没有真实实现来源时添加字体、间距、阴影、断点或颜色 token；局部状态值应继续记录为组件规则。
- **Don't** 用酸性绿填满大面积表面；它的稀缺性使执行状态可见。
- **Don't** 把本地工具、专项工作流和 Computer Agent 合并成同一个模糊身份。
- **Don't** 在移动端隐藏预算、授权后果、失败原因或文件上传边界来换取视觉简洁。
- **Don't** 让固定底部输入框遮挡最后一条消息、执行动作或交付物。
- **Don't** 以纯颜色、纯动画或无标签图标作为唯一状态表达。
- **Don't** 移除原生键盘焦点；若增加自定义焦点样式，应至少达到 Composer 的清晰度。
