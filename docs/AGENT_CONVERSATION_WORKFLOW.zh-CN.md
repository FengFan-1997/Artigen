# Agent 协作工作流

本规范定义主要产品体验；邀请、推广和运维进度不能替代工作流验收。实现覆盖设计对话与 Agent 运行详情，部署状态以正式 Handoff 和当前版本接口为准。

## 用户应当看到什么

1. 用自然语言提出任务，看到已有的计划、费用范围与执行入口。
2. 执行过程按顺序显示真实进展文字和工具调用。工具可以展开查看名称、用途、状态与时间；失败与成功明确区分。
3. 在主要对话输入框补充当前任务的文字要求。只有一个未完成 Agent 任务时更新该任务；多个任务时提示选择对应详情，避免发错对象。发送失败保留草稿，同一次重试复用幂等标识。
4. Worker 在下一次安全的模型调用边界读取补充要求，保存已消费标识到加密 checkpoint，再记录已纳入上下文。正在执行的工具不会被强行中断，也不会自动获得新的外部操作授权。
5. 刷新或重新打开时，历史记录按服务端事件标识分页恢复，实时流与历史去重。已完成任务中通过验证的文件可以点“基于此文件继续”，作为下一轮的输入，并在新任务中生成带父版本关系的新文件。

## 记录与上下文契约

- 所属用户鉴权后才读取 `/api/agent-runs/:runId/history`；缓存策略为 private/no-store。HTTP 分页游标独立于 SSE，不能因先收到最新事件漏掉早期记录；界面不截断为最近八条。
- 用户输入仍保存在加密 payload；事件只关联 payload 标识，鉴权后解密用于展示。过期 payload 或旧版没有关联标识的收件事件显示原有摘要，不伪造原文。保留时间沿用现有 Agent retention 策略，不承诺永久保存所有执行数据。
- 模型的公开进展文字使用用户语言，长度最多 500 字符；不展示 reasoning 字段。仅展示实际产生的内容，不插入固定段落伪装成执行叙述。工具卡目前展示服务端公开摘要，不展示原始命令参数、完整 stdout 或未脱敏日志。
- 接收与执行采用不同事件：收到输入不等于模型已经处理。进展叙述也不等于交付验证通过。
- Cloudflare / SiliconFlow / Ollama 兼容执行循环支持执行中补充和恢复消费去重。新要求使旧交付缓存与语义验证结果失效；收尾事务检查未消费输入，有遗漏则暂停等待继续。进入确定性最终验证后拒绝新补充，保留前端草稿。
- 费用、审批、接管、权限、工具执行证据和原有最终验证保持既有约束。跨运行输入只接受当前用户、当前设计会话中已成功任务的验证通过文件，服务端重新校验文件和对象存储归属、有效期；规划器只收到文件名和类型，实际内容仅随用户确认启动的 Agent 运行传入。
- 跨运行文件引用由 `agent_run_source_artifacts` 记录；相同文件名的后续产物自动关联 `parent_artifact_id` 并递增版本号，以便展示可追溯版本。源文件过期或原任务不成功时拒绝引用。

## 验收

- 真实模型公开进展、真实工具事件、补充要求与交付状态在同一会话中可读。
- 超过一页的历史、断线重连、刷新和切换任务不丢记录、不串任务、不重复插入。
- 执行中更改要求后，下次模型请求确实包含新要求；恢复 checkpoint 不重复添加；旧的已验证答案不能覆盖新要求。
- 发送失败保留输入与重试标识，主输入框补充不会创建第二个规划任务。
- 桌面和窄屏布局可读，工具卡可键盘展开；主要输入框始终可用。

## 当前边界与后续工作

执行中新增附件尚不支持，界面会明确提示并保留草稿。独立运行详情的已完成任务仍为只读；跨运行文件续做仅从原设计会话的交付卡片显式选择，不自动把所有历史文件带进新任务。旧 OpenAI Responses 执行器尚未接入新的执行中输入回调；当前默认兼容执行器是本轮验收对象。

仍需以真实设计任务检验：生成首版 → 执行中补充 → 查看调用 → 验证交付 → 在同一设计会话中选择上一版文件、修改并验证新版本。自动测试使用合成数据与 mock，不替代 DEV 的真实模型、文件下载和暂停恢复验收。
